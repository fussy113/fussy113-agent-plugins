# ja-writing — 日本語文書の作成・推敲パイプライン

tanteki(構成と簡潔さ)→ natural-japanese(自然さ)→ yomiyasu(最終推敲)の順に通し、1本の日本語文書に仕上げます。作業範囲は**文章の作成・推敲だけ**です。コードや設定の変更は含みません。

## 前提

3スキルが導入済みであること。未導入のスキルは、その段を飛ばして最終報告に書く。

## 鉄則

> **原文・資料にない事実・数値・条件を足さない。言い切りの強さと文の働きを変えない。**

## モード

- 原文(ファイル・貼り付け)がある → 推敲
- 資料や依頼だけがある → 作成
- 引数 `write` / `polish` があればそれに従う

## 実行手順

最初に、モードと適用する段を1文で伝える。途中は重要な発見・方針転換のみ伝える。

1. **tanteki**: tanteki スキルを読み込み、手順に従う。作成では構成を確認してから本文を書き、推敲では構成・重複・表を検査する。textlint を通す。エッセイやブログなど業務・技術文書でないものは、この段を飛ばす。
2. **natural-japanese**: natural-japanese スキルを読み込み、lint の検出を文脈で判断して自然さと AI らしさを直す。前段で決めた構成・見出し・用語は変えない。
3. **yomiyasu**: yomiyasu スキルを読み込み、比喩・主述・文末を最終推敲する。前段で決めた構成・用語は変えない。

指示が食い違うときの優先順位は、意味の保持 > 前段の決定 > 後段の文体調整とする。

## 完了条件

- 最終稿に対し、適用した段の検査(tanteki の textlint、natural-japanese の lint)を実際に再実行した。意味を変えずに直せる指摘は直し、残った指摘はそのまま報告した。飛ばした段の検査は実行せず、飛ばした理由を最終報告に書いた。
- ファイルを推敲したときは、原文を書き換えず、原文と同じフォルダにまだない名前で最終稿を保存した。

## 出力

最終稿 → 各段の主な変更点(変更のない段は省略) → 書き手に確かめたい点。

## 使用例

```
ja-writing で docs/design.md を推敲して
ja-writing write この議事メモから報告書を作って
```

## 関連

- `tanteki` / `natural-japanese` / `yomiyasu` — 各段で使う外部スキル。単体でも使える。
